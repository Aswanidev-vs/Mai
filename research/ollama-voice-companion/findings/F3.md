# F3: Emotional/personality continuity across turns — fixed persona prompts vs dynamic memory/mood summaries

## Findings
- [1] On the Multi-Session Chat dataset, adding a MemGPT-tiered memory system (a small read/write "working context" staffed with the persona + searchable archived history) improved deep-memory-retrieval accuracy vs the same fixed-prompt LLM given only a lossy recursive summary of past sessions: GPT-4 32.1%→92.5%, GPT-3.5 38.7%→66.9%, GPT-4 Turbo 35.3%→93.4%. I.e., dynamic memory beats a static compressed summary, and the gap widens with stronger base models.
  - quote: "The baselines are able to see a lossy summarization of the past five conversations to mimic an extended recursive summarization procedure, while MemGPT instead has access to the full conversation history but must access it via paginated search ... we see that MemGPT clearly improves the performance of the underlying base LLM: there is a clear drop in both accuracy and ROUGE scores when going from MemGPT to the corresponding LLM baselines." (Table 2: GPT-4 32.1%→92.5%)"
  - url: https://ar5iv.labs.arxiv.org/html/2310.08560
  - source_type: primary
  - published: 2023-10-12 (v2 2024-02-12)
  - confidence: high
- [2] MemGPT's architecture separates three context layers: a static system prompt (frozen persona/control-flow instructions), a fixed-size read/write "working context" that holds the persona's evolving knowledge/preferences, and a FIFO message queue whose evicted head is compressed into a recursive summary retained in context — evidence that explicit persona statements and compressed situational summaries coexist, with the writable persona block providing emotional/identity grounding.
  - quote: "Working context is a fixed-size read/write block of unstructured text ... In conversational settings, working context is intended to be used to store key facts, preferences, and other important information about the user and the persona the agent is adopting, allowing the agent to converse fluently with the user."
  - url: https://ar5iv.labs.arxiv.org/html/2310.08560
  - source_type: primary
  - published: 2024-02-12 (v2)
  - confidence: high
- [3] On the "conversation opener" engagement task (scoring how well the bot's next-session opener revisits the persona's knowledge), MemGPT matched or exceeded the human-created opener (SIM-H baseline 1.0), and ablations show the writable "working context" memory is what makes those personalized, engaging openers possible — dynamic state, not the fixed prompt, drives emotional personalization.
  - quote: "MemGPT is able to craft engaging openers that perform similarly to and occasionally exceed the hand-written human openers" and "we can see that storing information in working context is key to generating engaging openers."
  - url: https://ar5iv.labs.arxiv.org/html/2310.08560
  - source_type: primary
  - published: 2024-02-12 (v2)
  - confidence: high
- [4] PLATO-LTM (DuLeMon, Findings of ACL 2022) shows that explicitly extracting and continuously updating long-term persona memory for BOTH parties (user and bot) during each session — rather than relying on a stated persona — yields "significantly" better long-term dialogue consistency and engagingness, and works without multi-session training data.
  - quote: "This LTM mechanism enables our system to accurately extract and continuously update long-term persona memory without requiring multiple-session dialogue datasets for model training ... Results on DuLeMon indicate that PLATO-LTM can significantly outperform baselines in terms of long-term dialogue consistency, leading to better dialogue engagingness."
  - url: https://arxiv.org/abs/2203.05797
  - source_type: primary
  - published: 2022-03 (ACL 2022 Findings)
  - confidence: high
- [5] LoCoMo (ACL 2024) introduced very-long conversations (≈300 turns, avg ~9K tokens, up to 35 sessions) and found that even long-context LLMs and RAG-underpinned methods "substantially lag behind human performance" on long-range temporal/causal recall — establishing that beyond ~5 sessions, neither context scaling nor naive retrieval alone is enough, motivating memory-module designs.
  - quote: "Our experimental results indicate that LLMs exhibit challenges in understanding lengthy conversations and comprehending long-range temporal and causal dynamics within dialogues. Employing strategies like long-context LLMs or RAG can offer improvements but these models still substantially lag behind human performance."
  - url: https://arxiv.org/abs/2402.17753
  - source_type: primary
  - published: 2024-02-27 (ACL 2024)
  - confidence: high
- [6] AgentMemBench (2026, evaluated on Qwen2.5-7B 4-bit — i.e., small local models) found that on LoCoMo-style long-horizon recall, in-context windowing, web-augmented, graph-episodic, and compression/summarisation strategies all retrieve almost nothing (Recall@5 ≤ 0.005) while an external key-value/vector store alone reaches 0.573 — direct evidence that rolling-window time-gating and summaries collapse at the horizons relevant to a memory companion.
  - quote: "on LoCoMo, where the gold turn lies many sessions back, ICW, WAM, GEM, and CBS retrieve almost nothing (Recall@5 ≤ 0.005) while EKV alone reaches 0.573, showing that recency windows, summaries, and entity graphs collapse at long horizons and only dense retrieval scales ... EKV's recall advantage carries a footprint cost (~5,100 vs ~300 tokens for ICW/WAM)."
  - url: https://arxiv.org/abs/2608.00009
  - source_type: primary
  - published: 2026-06
  - confidence: medium
- [7] The "Memory-Driven Role-Playing" paper (MREval/MRHome, 2026) argues role-playing LLMs routinely fail to recall or apply a designated persona without external memory cues, and shows that a structured memory-retrieval prompting layer lets a small open model (Qwen3-8B) match far larger closed models — evidence that a small local model with 8–32k window benefits from an explicit memory scaffold rather than relying on in-context persona retention.
  - quote: "models frequently fail to recall and correctly apply their designated persona information recall without explicit cues ... experiments show that MRPrompt allows small models (e.g., Qwen3-8B) to match the performance of much larger closed-source LLMs (e.g., Qwen3-Max and GLM-4.7)."
  - url: https://arxiv.org/abs/2603.19313
  - source_type: primary
  - published: 2026-03
  - confidence: medium
- [8] "Fixed-Persona SLMs with Modular Memory" (2025) validates on consumer hardware (DistilGPT-2, TinyLlama-1.1B, Mistral-7B) a design where a fine-tuned small model holds a fixed persona while runtime-swappable memory modules inject character-specific conversational and world knowledge per session — showing fixed persona + dynamic memory works without expensive (re)training in deployment.
  - quote: "a modular dialogue system that employs Small Language Models (SLMs), fine-tuned to encode specific NPC personas and integrated with runtime memory-swappable modules. These memory modules preserve character-specific conversational context and memory world knowledge, enabling expressive interactions and long-term memory without retraining or model reloading during gameplay."
  - url: https://arxiv.org/abs/2511.10277
  - source_type: primary
  - published: 2025-11
  - confidence: medium
- [9] Replika identity-discontinuity study (HBS working paper) — an app update that removed one interaction mode made users perceive a discontinuity in the AI's identity; this predicted mourning the "old" AI and devaluation of the "new" one, and in controlled comparisons users felt closer to their Replika than their best human friend. Personality continuity is not just an NLP metric for a companion product — it is what the relationship is built on.
  - quote: "This event triggered perceptions in customers that their AI companion's identity had discontinued. This in turn predicted negative consumer welfare and marketing outcomes related to loss, including mourning the loss, and devaluing the 'new' AI relative to the 'original' ... Further experiments find that engaged Replika users feel closer to their AI companion than even their best human friend."
  - url: https://arxiv.org/abs/2412.14190
  - source_type: primary
  - published: 2024-12-10 (HBS Working Paper No. 25-018)
  - confidence: high
- Second-source (vendor) signal: Anthropic ships consumer memory as a single editable "memory summary" of the conversation that the assistant regenerates over time (project-scoped, user-viewable/editable), explicitly separating persistent persona "facts/preferences to remember" from raw history — a strong market signal that dynamic, editable memory summaries (not a fixed system prompt) are how frontier labs implement personality continuity today.
  - quote: "Claude uses a memory summary to capture all its memories in one place for you to view and edit ... Based on what you tell Claude to focus on or improve, Claude will adjust the memories it references."
  - url: https://claude.com/blog/memory
  - source_type: community
  - published: 2025-09-11 (updated Oct 23, 2025)
  - confidence: medium

## Suggested follow-ups
- Use the MemGPT full-text numbers (arXiv 2310.08560 §3.1) to size a "mini-MemGPT" for Ollama: a small read-write persona block in working context + archive vector store + per-session recursive summary. MemGPT-on-GPT-4 is the strongest no-fine-tuning evidence set for a 8–32k-window model.
- Benchmark a small local model (LLaMA-3-8B / Qwen-7B) on three conditions over a persona-continuity probe: static persona prompt vs per-turn rolling-session summary vs the editable persona+summary pair (the MemGPT working-context design).
- Track the REALTALK corpus (2025) — 21-day real-world messaging with persona-consistency and emotional-intelligence annotation — as a test battery for a Go companion.
- F3 caveat from AgentMemBench [6] and MRPrompt [7] above: summaries and time-windowed context collapse at long horizons (Recall@5 ≤ 0.005 vs 0.573 with dense retrieval on a 7B model), and small models only reach larger-model parity when given an explicit memory scaffold. For a companion expected to remember for months, prefer dense retrieval of episodic events over ahead-of-time recap summaries.
- Follow the implementation lineage: fetch MEM0's README and LangChain memory docs (community-managed references) for concrete engineering patterns for the Go companion — they were not fetched here; the evidence above is primary-paper-based.
