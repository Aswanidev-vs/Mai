# F4: Ollama & llama.cpp prompt-caching mechanics (cache_prompt / keep_alive / num_ctx interplay)

## Findings

- [1] **`keep_alive` (default `5m`) is purely a model-lifetime control — it does NOT cache prompts by itself, but without it the KV cache is lost on unload.** Official API docs (both endpoints): "`keep_alive`: controls how long the model will stay loaded into memory following the request (default: `5m`)". Accepted values (FAQ): duration string (`"10m"`, `"24h"`), number of **seconds** (`3600`), any negative number = keep loaded indefinitely (`-1`/`"-1m"`), `0` = unload immediately after the response. Server-wide default set by `OLLAMA_KEEP_ALIVE`; a per-request `keep_alive` overrides it. Setting `keep_alive:0` with an empty prompt unloads the model (`done_reason:"unload"`).
   - url: https://github.com/ollama/ollama/blob/main/docs/api.md (also https://docs.ollama.com/faq.md) / source_type: docs (GitHub + docs.ollama.com) / published: 2026 (main, current) / confidence: high

- [2] **Ollama's public API docs do NOT currently document a `cache_prompt` field** — neither `docs/api.md` on main nor the OpenAPI schema at `docs.ollama.com/api/generate.md` / `docs.ollama.com/api/chat.md` list it (both list only `keep_alive` among lifetime params). However, merged PR #16639 "Decouple prompt caching from context shift" (2026-06-11) adds "optional top-level `cache_prompt` to generate and chat requests", keeping the default: "omitted `cache_prompt` still sends `cache_prompt: true` to llama-server". The docs appear to lag the implementation — treat "cache_prompt documented in public API docs" as NOT yet true, but the field works in Ollama ≥ the PR's release.
   - url: https://api.github.com/search/issues?q=repo:ollama/ollama+cache_prompt (items #16635, #16639) / source_type: GitHub issue+PR (primary) / published: 2026-06-08/11 / confidence: high (implementation), high (documentation gap)

- [3] **Before PR #16639 (since the CGO-engine removal #16031), Ollama hardwired per-request `cache_prompt` to the public `shift` option** — one boolean, two jobs. `llm/llama_server.go`: `CachePrompt: req.Shift` (`:1398`, completion) and `"cache_prompt": req.Shift` (`:1987`, chat). Per-request default `Shift: req.Shift == nil || *req.Shift` ⇒ **unset ⇒ always `true`**: prompt caching was (and remains) **on by default for every `/api/generate` and `/api/chat` call**, independent of context size. The same `shift` boolean also drove llama-server's `--context-shift` launch flag with a *different* default (only when `numCtx < 8192`). Consequence (issue #16635): with `cache_prompt` forced on, fixed `seed`+`temperature` is nondeterministic — the long-standing ollama #5321/#12559/#4990 and upstream ggml-org/llama.cpp#2838 determinism bugs. The user-facing fix PR #5760 "Make llama.cpp's cache_prompt parameter configurable" (2024) stalled ~2 years and was closed stale.
   - url: https://api.github.com/search/issues?q=repo:ollama/ollama+cache_prompt (items #16635 body, #16639) / source_type: GitHub issue/PR (primary) / published: 2026-06-08..11 / confidence: high

- [4] **Conversation memory**: `/api/generate` returns a `context` (token-array) you could round-trip — now marked **`context` (deprecated)**; the docs say it "can be used to keep a short conversational memory". `raw:true` disables templating and "will not return a context". The modern path is `/api/chat`, which re-sends the **entire `messages` array** every request; Ollama re-renders the template each call, so cache-reuse gains only come from token-prefix matches against the previous request's processed prompt.
   - url: https://github.com/ollama/ollama/blob/main/docs/api.md / source_type: docs / confidence: high

- [5] llama.cpp `cache_prompt` semantics — per-request field, **default `true`** in llama-server: "Re-use KV cache from a previous request if possible. This way the **common prefix** does not have to be re-processed, only the suffix that differs between the requests. Because (depending on the backend) the logits are **not** guaranteed to be bit-for-bit identical for different batch sizes (prompt processing vs. token generation) enabling this option can cause **nondeterministic results**." Server-level flag `--cache-prompt, --no-cache-prompt` ("whether to enable prompt caching (default: enabled)", env `LLAMA_ARG_CACHE_PROMPT`); profile comparison is done against "the previous completion" from the same slot. Prompt *prefill could be triggered* via `n_predict:0` ("the prompt is evaluated into the cache" with no tokens generated).
   - url: https://raw.githubusercontent.com/ggml-org/llama.cpp/master/tools/server/README.md / source_type: docs + auto-generated flag reference / confidence: high

- [6] KV-cache re-use is prefix-based and now decoded by KV-shift: `--cache-reuse N` / per-request `n_cache_reuse` (default `0`): "min chunk size to attempt reusing from the cache via KV shifting, requires prompt caching to be enabled". A slot keeps its KV for the cached prefix; successive requests from the same runner reuse `tokens_cached` (completion timings) and `/slots` reports `cache_n` ("total tokens in context = `prompt_n + cache_n + predicted_n`"). Slot-to-request matching uses `--slot-prompt-similarity SIMILARITY` (default `0.10`; `0` disables). Idle-slot prompt caches can be persisted to disk: `--slot-save-path` + `POST /slots/{id}?action=save|restore|erase`, and `--cache-ram N MiB` (default 8192) limits in-RAM prompt-cache.
   - url: https://raw.githubusercontent.com/ggml-org/llama.cpp/master/tools/server/README.md (arg table + `/completion` + `/slots` sections) / source_type: docs / confidence: high

- [7] **The KV cache is sized by context, and `num_ctx` (Ollama) maps to `--ctx-size` (llama.cpp)**: `-c, --ctx-size N` "size of the prompt context (default: 0, 0 = loaded from model)". Cache geometry: `-ctk/--cache-type-k` and `-ctv/--cache-type-v` (allowed `f32, f16, bf16, q8_0, q4_0, q4_1, iq4_nl, q5_0, q5_1`; **default `f16`**), `-fa, --flash-attn [on|off|auto]` (default `auto`), `-kvo, --kv-offload` (default enabled). Ollama's env equivalents: `OLLAMA_KV_CACHE_TYPE` (global for ALL models — default `f16`, `q8_0` ≈ 1/2 memory, `q4_0` ≈ 1/4, notable quality impact at high GQA like Qwen2) and `OLLAMA_FLASH_ATTENTION=1|0` (auto-enabled when supported). A `num_ctx` change → new ctx-size → KV cache alloc/layout changes → previous cache content does not carry over cleanly.
   - url: https://docs.ollama.com/faq.md ("How can I enable Flash Attention?", "How can I set the quantization type for the K/V cache?") and server README arg table / source_type: docs / confidence: high

- [8] **Interplay & cache-loss triggers in the voice-companion ReAct loop:**
   - `keep_alive` (or `OLLAMA_KEEP_ALIVE`, default 5 min) keeps the model **and its KV cache/slots resident** across turns — that is the precondition for cross-turn reuse; after idle-unload or restart the next call is a full cold re-eval. llama-server sleep mode (`--sleep-idle-seconds`) also unloads "the model and its associated memory (including the KV cache)".
   - `num_ctx` mismatch between calls re-creates the runner → cache lost; raising `num_ctx` increases KV memory (and with Flash Attention off, K/V cached large). 
   - `OLLAMA_NUM_PARALLEL` (default 1) multiplies required RAM by `OLLAMA_NUM_PARALLEL × OLLAMA_CONTEXT_LENGTH`; a parallel ctx size per slot is `ctx × parallel` (FAQ: "a 2K context with 4 parallel requests results in an 8K context").
   - default context length (2026 docs, VRAM-based): <24 GiB → 4k; 24–48 GiB → 32k; ≥48 GiB → 256k (`OLLAMA_CONTEXT_LENGTH` + per-call `options: {num_ctx: N}` override; older FAQ asserts a flat 4096 default).
   - url: https://docs.ollama.com/faq.md, https://docs.ollama.com/context-length.md, + server README / source_type: docs / confidence: high

- [9] **What breaks prefix reuse — practical checklist (llama.cpp semantics behind Ollama's prompt):** (a) changing the system prompt or any token in the history — cache reuse only covers the matching prefix, and anything from the first differing token onward must be re-processed; the rendered history must match byte-for-byte AFTER template rendering, and since Ollama re-renders the template every call, equivalent-but-not-identical chat text (whitespace/newlines/JSON spacing) creates different token prefixes and misses the cache; (b) conversation splitting/insertion in the middle — the prefix changes, so every request after that edits the cached sequence starts re-processing earlier; (c) `num_ctx` mismatch → KV-cache geometry change → full re-eval; (d) sampling/`seed` reproducibility — the documented warning: "enabling this option can cause nondeterministic results" (this is the #5321 / #12559 / #4990 determinism bug class, root-caused to the always-on prompt cache); and (e) every call where `keep_alive` has expired / the model was unloaded — cold start.
   - url: https://raw.githubusercontent.com/ggml-org/llama.cpp/master/tools/server/README.md + https://api.github.com/search/issues?q=repo:ollama/ollama+cache_prompt (#5321) / source: docs + primary issue + bugs / confidence: high (docs statements), medium-high (inference of the "divergence" detail — llama.cpp's "common prefix … suffix" wording)

- [10] **Empirical observability**: to verify cache reuse from the client: /api/generate reports `prompt_eval_count` / `prompt_eval_duration` — a short `prompt_eval_duration` on a large `prompt_eval_count` indicates a cache hit; to confirm the llama.cpp-side they have `tokens_cached` and `/slots` cache_n (and `prompt_progress: {total, cache, processed}` when `return_progress:true`). Note that Ollama's response JSON does not expose `tokens_cached` today.
   - url: https://raw.githubusercontent.com/ggml-org/llama.cpp/master/tools/server/README.md (/completion timings) + https://github.com/ollama/ollama/blob/main/docs/api.md / source_type: docs / confidence: high

- For the ReAct loop, `cache_prompt` being on-by-default means you get prefix reuse for free as long as the system prompt is byte-stable (keep it in a template/invariant place; keep message order stable) — worth an experiment comparing "grow a single conversations array" (cache-reuse friendly) vs "resend a fresh subset each step" (cache-breaking) as the loop iterates.
- Recommend `OLLAMA_NUM_PARALLEL` default 1 and a fixed `num_ctx` for a single-user companion (state per-request `options: {"num_ctx": X}` consistently), and decide whether to set `OLLAMA_KEEP_ALIVE=-1` to avoid the 5-min idle unload killing the KV cache mid-conversation.
- If determinism under `seed` is ever needed (e.g. replayable demos), note the current requirements are `shift:false`-style toggles; there's no Ollama-documented per-request `cache_prompt:false` yet — verify against the PR's release notes.
